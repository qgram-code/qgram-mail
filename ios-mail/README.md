# QGram Mail для iOS

Нативное iOS-приложение почты QGram на SwiftUI. Интерфейс собран по макету
«Дизайн мобильного почтового приложения» (тема Nocturne, тёмная тема),
данные — **живые, из qgram API** (`https://qgram.fun`, см. `API_USAGE.txt`).

- **Язык / UI:** Swift 5, SwiftUI, минимум **iOS 16.0**, iPhone + iPad.
- **Bundle ID:** `fun.qgram.mail`, версия `1.0 (1)`.
- **Домен ящиков:** `@qgram.fun` (IMAP/SMTP — `mail.qgram.fun`).
- **Отдельно от `ios/QGram`** — это второе приложение, а не экран внутри старого.

## Как работает вход

Почта привязана к аккаунту qgram, отдельного логина в неё нет:

1. `POST /api/login` — логин и пароль аккаунта QGram.
2. Если аккаунт с 2FA, приходит `2fa_required` + `challenge_token`; код с почты
   уходит в `POST /api/login/2fa`.
3. Bearer-токен сохраняется в **Keychain** (`TokenStore`) и подставляется
   в заголовок `Authorization` всех запросов.
4. `GET /api/mail/account` — если ящика ещё нет (`exists: false`), показывается
   онбординг: `POST /api/mail/setup` создаёт `имя@qgram.fun` и один раз отдаёт
   пароль приложения для внешних IMAP/SMTP-клиентов.
5. Выход — `POST /api/logout` + очистка Keychain (Настройки → «Выйти из аккаунта»).

Если сервер отвечает 401, приложение само возвращается на экран входа.

## Что подключено к API

| Экран | Эндпоинты |
| --- | --- |
| Вход | `POST /api/login`, `POST /api/login/2fa`, `GET /api/me`, `POST /api/logout` |
| Онбординг | `GET /api/mail/account`, `POST /api/mail/setup` |
| Входящие / папки | `GET /api/mail/messages`, `GET /api/mail/folders` |
| Письмо | `GET /api/mail/messages/<folder>/<num>` (+ `?peek=1` для превью в списке) |
| Свайпы и панель письма | `POST /api/mail/messages/<folder>/<num>/action` (`delete`, `spam`, `archive`, `inbox`, `read`, `unread`, `star`, `unstar`) |
| Поиск | `GET /api/mail/messages?q=` (область «Все ящики» — по всем шести папкам) |
| Новое письмо / ответ | `POST /api/mail/send` (`to`, `cc`, `subject`, `body`, `in_reply_to`) |
| Настройки | `POST /api/mail/password` (новый пароль приложения), состояние и квота из `GET /api/mail/account` |

Не подключено намеренно: **вложения** (API отдаёт только имя/тип/размер, скачивания
нет) и **пуш-уведомления** (`/api/push/devices` требует APNs-ключей и entitlement).

## Как открыть и собрать

```bash
open ios-mail/QGramMail.xcodeproj
```

Дальше в Xcode 15+: схема **QGramMail**, своя команда разработчика в
*Signing & Capabilities* (проект идёт без `DEVELOPMENT_TEAM`), запуск на
симуляторе или устройстве.

Проектный файл и иконка генерируются скриптами; после добавления или удаления
файлов:

```bash
python3 ios-mail/scripts/generate_xcodeproj.py
```

```bash
python3 ios-mail/scripts/generate_appicon.py
```

## Релиз

Сборка релиза (архив + IPA) — только на macOS с Xcode 15+:

```bash
TEAM_ID=ABCDE12345 ios-mail/scripts/build_release.sh
```

Скрипт перегенерирует иконку и проект, соберёт `Release`-архив
(`build/QGramMail.xcarchive`) и экспортирует IPA в `build/export/`.
Для App Store / TestFlight — `METHOD=app-store`, для внутренней раздачи —
`METHOD=ad-hoc` (по умолчанию).

Что проверить перед выкладкой:

- вход обычным аккаунтом и аккаунтом с 2FA;
- создание ящика на свежем аккаунте (`can_create: false` показывается плашкой);
- отправка письма и поведение при исчерпанном лимите (`send_failed`);
- состояние `nosend`: баннер во входящих и экран «Отправка приостановлена»;
- выход из аккаунта — токен удаляется из Keychain, списки очищаются.

```
ios-mail/
├── QGramMail.xcodeproj/          # сгенерированный проект (objectVersion 56)
├── scripts/
│   ├── generate_xcodeproj.py     # пересборка проекта по файлам на диске

    ├── App/                      # точка входа, Session (вход), MailStore, настройки, таб-бар
    ├── Core/                     # модели, клиент qgram API, Keychain
    ├── DesignSystem/             # палитра Nocturne, акценты, общие компоненты
    ├── Features/
    │   ├── Auth/                 # вход через QGram + 2FA
    │   ├── Onboarding/           # создание ящика на @qgram.fun
    │   ├── Mail/                 # список писем, письмо, ящики
    │   ├── Search/               # серверный поиск с областями
    │   ├── Compose/              # новое письмо и ответ
    │   ├── Settings/             # аккаунт, ящик, стиль, поведение, IMAP/SMTP

    └── Resources/                # Info.plist, Assets.xcassets (иконка, акцент)
```

## Экраны

| Экран | Что внутри |
| --- | --- |
| Вход | логин/пароль QGram, шаг с кодом 2FA, ошибки прямо с сервера |
| Онбординг | выбор имени ящика на `@qgram.fun`, одноразовый пароль приложения с копированием |
| Входящие | крупный заголовок, поиск, плашка квоты, свайпы (архив/удалить/непрочитано), pull-to-refresh, подгрузка «Показать ещё», баннеры ошибок и ограничения отправки |
| Письмо | тема, метки DKIM/SPF/DMARC (из `auth_results`), отправитель, текст, вложения, быстрые ответы, панель ответа |
| Ящики | шесть папок со счётчиками из `/api/mail/folders`, карточка ящика с квотой |
| Поиск | серверный поиск по областям «Все ящики / текущая папка / непрочитанные» |
| Настройки | аккаунт QGram, адрес и состояние ящика, лимит отправки, акцентный цвет, поведение, параметры IMAP/SMTP, сброс пароля почты, выход |
| Блокировка | статус и причина ограничения из `account.disabled_reason`, обновление статуса |

## Настройки приложения

Живут в `SettingsStore` (UserDefaults) и применяются сразу:

1. **Акцентный цвет** — шесть вариантов, первые четыре из макета (`#9184D9`,
   `#7FB0D9`, `#C08A6A`, `#7FC0A0`). Производные оттенки считаются в `AccentTheme`.
2. **Показ квоты на главном экране** — плашка «Отправлено сегодня».
3. **Текст письма в списке** — подтягивает первые строки писем через `peek=1`
   (12 верхних писем папки); выключается, если хочется меньше запросов.
4. **Свайпы** и **превью на экране блокировки** — как в макете.

## Отличия от прототипа

- Иконки — SF Symbols вместо SVG-путей макета.
- Переписки: qgram API не отдаёт треды, поэтому письмо показывается целиком
  одной карточкой, а не сворачиваемой цепочкой.
- Вложения показываются метаданными: скачивание доступно только по IMAP.
